# Local-only rehearsal server artifact

`pnpm --filter @mdbase/connect-server build:local` is an explicit BUILD operation:
ordinary tsc first emits the managed literal (`false`), then the local build step
emits the local literal (`true`) in that output. Regular `build` and the managed
Dockerfile always emit false. Do not deploy a local artifact to a managed service.

Both the compile literal and `MDBASE_CONNECT_ENVIRONMENT=local` with exact
`PUBLIC_URL=http://127.0.0.1:<port>` are required to start a local control plane.
Local factory URLs must be exact HTTP IPv4-loopback origins. The canonical
migration CLI/target creator and Worker client reuse the same authenticated
requests, metadata checks, signer, original genesis and claim verification.
They do not grant custody, fabricate receipts, bypass a claim or alter data.

Managed server artifacts reject local runtime configuration. LAB continues to
pin its existing target origin and staging/production do not get a local alias.
The only native HTTP CPP audience is in the separately compiled local hosted
WASM artifact; ordinary WASM remains HTTPS-only. Keys/roots are generated by the
isolated local stack, never selected from a request or copied from LAB.

This is the transport/build boundary, not a full migration PASS. Timers,
installation/browser local-build ports, legacy source, S3 and archive adapters
must also be configured and checked by the owning local stack/runner.
