# Native completion authentication vector

`completion-v1.txt` is generated independently with the existing SDK's canonical
CBOR codec and Node's SHA-256/Ed25519 implementation. Rust tests compare exact
unsigned/completed CBOR, domain digest, public key and signature, and verify with
the existing log-service signature checker.

All IDs, key material and hashes are deterministic **test-only** fixtures. The
header/FINISH/genesis labels are synthetic: this authenticates the completion
schema/signature phase only, not a complete cut, signer authority or currentness.

From the repository root, with Node 22.22 or newer:

```sh
node --experimental-transform-types crates/backup-verify/tests/vectors/generate-completion.mjs
```

## Complete-cut vectors

`cut-*-v1.txt` is independently generated by `generate-cut.mjs` using the SDK
codec and Node crypto. It contains exact signed history, six-section page chains,
header/FINISH, strict inventory roots and completion/trust for ordinary, compacted,
and indexed captures. The indexed case has publisher != signer and extra committed
metadata roots. The near-9-MiB case records independent whole-object hashes instead
of committing the large deterministic filler twice. Rust tests compare all bytes
and verify full closure; no vector field may be ignored.

```sh
node --experimental-transform-types crates/backup-verify/tests/vectors/generate-cut.mjs
```

No network, provider, release key or deployed capture operation is involved.
