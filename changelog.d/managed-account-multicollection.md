## Fixed

- Managed hosted account migration now processes every held collection in two phases: every member first reaches the verified pre-cutover pause with its timers imported, then each is cut over in turn and the account flips once using combined cutover and timer evidence. A failure before the first cutover routes the whole set back (a scoped archive is not restarted and needs a fresh attempt); after it the driver only moves forward. Original ambiguous Worker launches are never replayed, and run bindings from the earlier driver are refused rather than reinterpreted. Transferred history is excluded. The account's single recorded migration start selects the job: an ordinary archived start uses this managed path in LAB, staging and production, while a LAB fixture start keeps its singleton contract; missing, repeated, unknown or cross-environment starts refuse. Live managed multi-collection qualification is pending.
- Transferred hosted history is no longer routed to the hosted migration Worker. An ordinary hosted→local promotion leaves that id as the owner's local collection, so it and any later cloud copy of it use the control plane's own deployments; held collections keep their migration route before and after the flip.
