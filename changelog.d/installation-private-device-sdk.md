## Added

- SDK: an app that hosts its own replica (`createMdbase`) can open an existing Private collection with it, as a device of that collection. Listing `offline.replica` in the declaration's capabilities (optional or required; optional keeps cloud-copy sign-in working where device access is not offered) asks for device access at sign-in, and a server that does not know or does not grant the request leaves an ordinary cloud-copy sign-in; shared Private collections appear in `snapshot.collections` with `mode: "private"`. A device without the key reads the new `needs_unlock` phase (`mode`: `password`, `strict` or `none`), and `mdbase.unlock(collectionId, {password})` or `{recoveryKey}` unlocks it without a reload; a wrong secret stays on `needs_unlock` with `problem` set. The secret is wiped when the call settles and never stored. Needs a Connect server that admits installations as Private devices. The app runtime gains one fixed-purpose signer for this, the account-key fetch proof for its own connector and device (`rt_app_account_key_fetch_sign`); an older app runtime answers `unlock_unavailable`.
- App UI: the collection view shows a Private collection this device cannot open yet as a plain locked state instead of failing to compile against the new `needs_unlock` phase.
- SDK: retyping an encryption password or recovery key no longer spends the account's sealed-key fetch limit on every attempt. A mistyped recovery key and a password under the 12-character minimum are refused in the app without a request, and after a wrong secret the sealed bundle is kept in memory for the next attempt on the same locked collection (used only while the account key version is unchanged, dropped on unlock or close).
