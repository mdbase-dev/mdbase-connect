## Breaking

- SDK: every client method now answers in plain JSON. A record's `frontmatter`, `effective` and `values`, a contract's `fields`, a description's `definition` and `schema`, presence `state` and conflict values are `JsonValue`, and a data map is an object instead of a `Map`. Read `record.frontmatter.title` where you read `record.frontmatter.get("title")`, and delete the app's own `toPlain` wrapper. `1.0` reads as `1`, an integer beyond 2^53 reads as a decimal string, and integer-like keys come first in an object; `update(record, { patch })` still never writes those back by accident. Writes accept plain data as before, and `Float64`, `bigint` and `Map` where the exact form matters.
- SDK: the root's `RecordView`, `Receipt`, `QueryResult`, `QueryUpdate`, `Conflict`, `ConflictEntry`, `ConflictValue`, `Peer`, `QueryGroup` and `QueryMetadata` are the plain types, joined by `DescribeResult`, `TypeSummary`, `ContractSummary`, `ContractImplementation`, `Backlink`, `BacklinksResult`, `PendingMutation`, `ViewDescriptor`, `ViewSource`, `JsonObject` and `Plain<T>`. The exact types stay under `wire`. For an exact answer, call `client.call(method, params)` without a codec and decode it with a `wire` codec; `client.call` with a codec now decodes plain.
- SDK: the `details` of a problem, issue or incident are plain JSON at every layer, including `MdbaseError.details`, which is typed `JsonValue`. Read `error.details.availability` where you read `error.details.get("availability")`.
- SDK: a record session's snapshot `frontmatter` is a plain object, and `ContractRecordView.fields` and `ContractProjection.fields` are plain objects.
- SDK: `JsonLike` is renamed `JsonValue`.
