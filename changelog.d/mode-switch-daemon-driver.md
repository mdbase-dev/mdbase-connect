## Changed

- The daemon now drives confirmed collection mode switches to completion in the background across restarts, `retry_at` token-drain windows, `503 not_ready` finishing retries, `409 mode_source_changed` preflight retries, and HTTP 429 rate limits, surfacing person-needed states (`waiting_for_devices`, `keyed_owner_required`, `waiting_for_device`) as collection notices instead of cancelling on retryable errors.
- `mdbase sync mode` and `mdbase sync mode-status` print concise plain-language status by default (keeping `--json` unchanged), wait briefly during fast phases before handing off to the background driver, make the target mode optional with `--cancel`, remove `--resume`, and note in the confirmation prompt that connected apps will need to be reconnected.
- Removed the dead `mdbase sync disable` command and its daemon/desktop IPC path, recorded mode switches in daemon activity, pointed `mdbase sync enable` on already-synced collections to `mdbase sync mode`, and replaced the raw device UUID in the cloud-copy-enabled notice with plain wording.
